# Съёмки — календарь фотографа (Android)

Приложение работает через то же облако Cloudflare R2, что и Photo Gallery на ПК:
события, заметки и референсы лежат в бакете в папке `_calendar/`.

## Сборка APK (без Android Studio)
1. Создайте приватный репозиторий на github.com и загрузите в него содержимое этой папки
   (вместе с `.github/`). Папку `node_modules` загружать не нужно.
2. Вкладка **Actions → Build APK → Run workflow**.
3. Через 5–8 минут скачайте артефакт **Shoots-APK**, распакуйте, перенесите `app-debug.apk` на телефон и установите
   (разрешите установку из неизвестных источников).

## Подключение облака
- На ПК: Photo Gallery → Настройки → «Скопировать настройки для телефона».
- На телефоне: вкладка «Настройки» → вставьте строку → «Сохранить и проверить». Либо введите Account ID / Access Key / Secret / Бакет вручную.

## CORS — подробно

**Зачем.** Приложение на телефоне ходит в ваш бакет R2 напрямую (из встроенного браузера WebView), без своего сервера. Браузер
разрешает такие запросы, только если бакет явно сказал: «этому источнику можно». Это и есть правило CORS. Без него
в приложении будет ошибка «Failed to fetch», хотя ключи верные. Галерея на ПК и сайты клиентов от этого правила не зависят,
оно нужно только телефону. Правило безопасно: доступ всё равно требует ваших ключей.

**Способ 1 — автоматически (проще).**
1. Cloudflare → R2 → Manage API Tokens → создайте токен с правами **Admin Read & Write** (обычный Object Read & Write не умеет менять CORS)
   и впишите его Access Key / Secret в настройки Photo Gallery на ПК.
2. Photo Gallery → Настройки → **«Подготовить бакет для телефона»**. Программа добавит правило и передаст телефону список клиентов.
3. После этого токен можно заменить обычным (Object Read & Write только на ваш бакет): правило CORS останется.

**Способ 2 — вручную в Cloudflare.**
1. dash.cloudflare.com → **R2 Object Storage** → откройте свой бакет.
2. Вкладка **Settings** → блок **CORS Policy** → **Add CORS policy**.
3. Выберите вкладку **JSON** и вставьте:

```json
[
  {
    "AllowedOrigins": ["https://localhost", "http://localhost", "capacitor://localhost"],
    "AllowedMethods": ["GET", "PUT", "DELETE", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 86400
  }
]
```
4. **Save**. Применяется сразу (иногда до минуты).

**Что означает каждая строка.**
- `AllowedOrigins` — «адрес», с которого приложение обращается к серверу. Приложение работает как `https://localhost`; остальные два — запас.
  Это не ваш сайт, поэтому `*` ставить не нужно.
- `AllowedMethods` — GET читает события и фото, PUT сохраняет, DELETE удаляет референсы, HEAD проверяет подключение.
- `AllowedHeaders: ["*"]` — приложение подписывает запросы заголовками (Authorization, x-amz-*), их нужно разрешить.
- `ExposeHeaders: ETag` — чтобы приложение видело версию файла.
- `MaxAgeSeconds` — на сколько браузер запоминает разрешение (сутки).

**Если не работает.**

| Симптом | Причина и решение |
|---|---|
| «Failed to fetch» при сохранении настроек | Правила CORS нет или в нём нет `https://localhost`. Проверьте JSON: без опечаток и лишних запятых |
| 403 / SignatureDoesNotMatch | Неверный Access Key/Secret, Account ID или имя бакета. Вставьте строку из программы заново |
| 403 только при сохранении/загрузке | У токена права только на чтение. Нужен Object Read & Write на этот бакет |
| «Не удалось включить CORS» на ПК | У токена нет Admin-прав: используйте способ 2 |
| Правило добавили, но не помогает | Подождите минуту, закройте и откройте приложение на телефоне |

## Уведомления и виджеты
- При первом запуске разрешите уведомления и «Будильники и напоминания».
- Виджеты: долгое нажатие на рабочем столе → Виджеты → «Съёмки»: 2×2 (следующая), 4×2 (три), 4×4 (шесть).
